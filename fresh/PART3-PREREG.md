## 1. The question this rung answers

Does our independent, from-spec implementation of the whole-brain LIF model reproduce the reference simulation output for the sugar experiment — the per-neuron firing-rate pattern of `sugarR.parquet` — to a pre-stated standard?

**Language discipline (binding on every report of this rung).** `sugarR.parquet` is Shiu et al.'s *simulation output*, not animal data (Part 1 verdict). Agreement with it is **reproduction of a reference simulation** — "model-vs-model agreement" — and will be worded exactly that way. It is not, and will never be reported as, biological validation, agreement with a living fly, or evidence about animal electrophysiology or behaviour. (Reviewer 3, condition C.)

## 3. The upstream protocol, as read — and its ambiguities

The reference file records no parameters (only the experiment name), so the protocol is reconstructed from the code that produced it: `example.ipynb` and `model.py` of the upstream repository at commit `91bdd1e` (reading log: `PART2-READING-LOG.md`). The producing call (notebook cell 7) is:

```
run_exp(exp_name='sugarR', neu_exc=neu_sugar, **config)
```

with **no `params` argument** — so `default_params` governed, unmodified. The protocol is therefore:

| Element | Value | Source |
|---|---|---|
| Driven population | `neu_sugar` = the **21 right-hemisphere labellar sugar GRNs only** — no second input class, no silencing, no other population | notebook cell 3 (list), cell 7 (call) |
| Drive | Poisson, `r_poi` = **200 Hz** per driven neuron (Amendment Pass 3 — the code default is 150 Hz; the choice of 200 Hz and its evidence are in A1 below); each event injects `w_syn × f_poi` = 0.275 mV × 250 = **68.75 mV directly into `v`**; driven neurons' refractory variable set to 0 (no refractory cap while driven) | `model.py` defaults + `poi()` (reading log); rate choice per §3/A1 |
| Trials | `n_run` = **30** | `model.py` default |
| Trial duration | `t_run` = **1000 ms**; spikes recorded over [0, 1.0 s) | `model.py` default; Part 1 file check |
| Integration | dt = **0.1 ms**, `method='linear'`, fresh network build per trial | `model.py` (reading log) |
| Network | All 127,400 v630 neurons; all 14,687,178 edges; weight = count × sign × 0.275 mV; **no synapse threshold** | `model.py` (reading log); Part 1 counts |
| Readout | Every spike of every neuron (one whole-group monitor) | `model.py` (reading log) |

**Ambiguities found, and the choice made for each (named here so the panel reviews the choices, not just the numbers):**

- **A1 — drive rate: notebook prose says 200 Hz, code default says 150 Hz; the reference file's own statistics settle it at 200 Hz.** The history, in order. The markdown above the producing cell (cell 6) states "By default, the neurons are excited at 200 Hz", but `default_params` sets `r_poi = 150 Hz`, and the producing call passed no override. The original reconstruction therefore chose **150 Hz**, on the reasoning that the code is what ran — the prose cannot have executed — corroborated by the fact that when the notebook *did* want a different rate (cell 13, `sugarR_100Hz`), it passed a modified `params` explicitly and the `sugarR` call did not; our Part 2 implementation and smoke run used 150 Hz on that basis. **That choice was superseded by evidence, before any validation trial ran.** The reference-only discrimination check (Reviewer 1's R3(ii), run in Amendment Pass 2 and recorded in full below) reads the generating rate straight out of the reference file: the 21 driven right sugar GRNs fire at mean **196.8 Hz** (median 197.3, range 191.3–202.1), while every undriven control population fires at exactly **0.0 Hz**; under this model's drive a driven neuron fires at close to the Poisson rate by construction, so the driven rate reads out the generating rate — ~200 Hz, not 150 Hz (150 Hz sits 47 Hz from the observed mean against a per-neuron spread of a few Hz, and network input cannot explain the gap because the controls are silent). The paper corroborates: 455 neurons respond at 200 Hz drive versus 45 at 10 Hz, and the file has 448 active neurons. **Choice (Amendment Pass 3, panel decision delegated by Angelic, 23 Nov 2026): 200 Hz is the primary, confirmatory drive rate; 150 Hz becomes the pre-declared non-confirmatory sensitivity arm (§4.1).** Keeping a primary the document itself had recorded as "a likely mis-specification" would have wasted the confirmatory run and still required a new preregistration afterwards; the switch is made now, before the freeze, as a formal amendment — never a quiet edit. **Reconstruction record (preserved in full):** the producing cell is notebook cell 7 (`run_exp(exp_name='sugarR', neu_exc=neu_sugar, **config)`, with no `params` argument); the driven list is defined in cell 3; the conflicting prose is the cell 6 markdown ("By default, the neurons are excited at 200 Hz"); the code default is `default_params` in `model.py` at upstream commit `91bdd1e`, which sets `r_poi = 150 Hz`. The 200 Hz figure is therefore labelled **"protocol established by reference-only discrimination evidence, not read from the reference parquet's own parameter record"** — the parquet records no parameters (§2, A2), so the choice rests on the file's driven-rate statistics plus the notebook prose, against the code default. The 150 Hz arm must **never** be used to rescue a failed 200 Hz reproduction: if the 200 Hz rung fails, the FAIL path (§9) runs on the 200 Hz result, and the 150 Hz arm is governed by §8.2.

**Methods read (Amendment Pass 2, Reviewer 1 R3(i)).** I have now read the Shiu et al. *Nature* 2024 Methods text (DOI 10.1038/s41586-024-07763-9, sections "Computational modelling" and "Computational modelling of water and sugar GRN activity"). It states: "GRNs were activated at particular frequencies using Poisson distributed input to generate 10–200 Hz firing (sugar) or 20–260 Hz firing (water)"; "30 simulations of 1,000 ms for each experiment were performed"; and W_syn was chosen "such that activation of sugar GRNs at 100 Hz resulted in roughly 80% of maximal MN9 firing". The paper's figures sweep the drive rate (Fig. 1d: 10–200 Hz), and its main text is explicit that "absolute firing rate predictions are unlikely to be accurate". **The Methods text states no single canonical rate for the released sugarR file** — the 150 Hz figure rests only on the code default, the 200 Hz figure only on the notebook prose, and neither is confirmed by the paper. The ambiguity stands as a paper-level fact, not a reading failure; it is the reference file's own statistics (next paragraph) that discriminate the two rates.

**Reference-only discrimination (R3(ii), computed before the freeze).** The reference file's own statistics DO discriminate the two rates, and they favour 200 Hz: the 21 driven right sugar GRNs fire at mean **196.8 Hz** (median 197.3, range 191.3–202.1, n = 21) in the reference file, while the undriven control populations — left sugar GRNs, bitter GRNs, water GRNs — fire at exactly **0.0 Hz** (§2.1). Under the model's drive (68.75 mV kick per Poisson event, refractory removed while driven — §3 table), a driven neuron fires at close to the Poisson rate by construction, so the driven rate reads out the generating drive rate: ~200 Hz, not 150 Hz (150 Hz sits 47 Hz from the observed mean, against a per-neuron spread of a few Hz; network input cannot explain the gap, since the undriven control populations are completely silent). Corroboration: the paper reports 455 neurons responding at 200 Hz drive versus 45 at 10 Hz (main text, Fig. 1d); the file has 448 active neurons. **Consequence, stated plainly:** the reference-only evidence says the file was most likely generated at 200 Hz, so the 150 Hz primary protocol this document originally carried was a likely mis-specification. Amendment Pass 2 (which ran this check) kept 150 Hz as the primary — Reviewer 1's R3 as written, specified before the check existed — and pre-declared a 200 Hz arm, recording the finding in full so the panel and Angelic could decide before the freeze. That decision has now been taken: Angelic delegated it to the panel, the panel voted to switch, and **Amendment Pass 3 makes 200 Hz the primary confirmatory protocol and 150 Hz the non-confirmatory sensitivity arm** (§4, §4.1, §8.2). The switch is a formal amendment to this preregistration, made before the freeze and before any trial ran — not a quiet edit, and not a new preregistration, because no result exists yet that the switch could be accused of chasing.

**Hemisphere note (from the same Methods read).** The Methods state "we performed unilateral left hemisphere activation for all simulations, except for Extended Data Fig. 1d", while the notebook's driven list is the 21 right-hemisphere GRNs — and the paper elsewhere notes the FAFB volume was found left–right inverted, with "right hemisphere GRNs" in the paper corresponding to "left hemisphere GRNs" described previously. The file's own MN9 asymmetry (L 93.3 > R 61.8 Hz, contralateral stronger per the main text) is consistent with the notebook's right-hemisphere list. The driven population in this preregistration is defined by the literal ID list, not by a hemisphere label, so the protocol is unaffected; the inconsistency is recorded here so it is never discovered as an excuse after the fact.
- **A2 — the reference does not record its own parameters.** The rate, duration and population above are a reconstruction from the producing call at a pinned upstream commit, not values read out of the file. If the released file was in fact produced by a different call than the notebook shows, this rung would be comparing against a mis-specified protocol — that possibility is exactly what the FAIL diagnosis path (§9) interrogates last, and it is stated here so it is never discovered *as an excuse* after the fact.
- **A3 — upstream's rate-table convention drops silent neurons.** `utils.get_rate` tabulates only neurons present in the spike table; the notebooks patch the gaps with `fillna(0)` at call sites, and its standard deviation is the population SD (ddof=0). **Choice:** this preregistration defines its own rate computation explicitly (§6) over all 127,400 IDs with explicit zeros, and does not inherit the upstream convention silently.
- **A4 — the `w` clause.** Upstream's reset string contains `w = 0`, a variable its neuron equations never define; Part 2 established experimentally that at Brian2 2.9.0 the clause is a **silent no-op** (bit-identical spike trains with and without it). Our frozen reset omits it. Wording rule (Reviewer 3, condition D, as corrected by Reviewer 1): this is **removal of a statement shown to have no effect under these tests** — the evidence is Part 2's before/after tests (bit-identical spike trains with and without the clause under the same seed; no `w` variable created on the group; weight vectors verified before and after). What upstream's source contains, what Brian2 2.9.0 executes, and what our implementation does are three distinct facts, and no report may describe the omission as a behavioural correction to the published model — and "ineffective" must never be claimed in general, only "no effect under these tests".

## 4. Our design

One run of the frozen runner (`ctb.brain.runner.run_experiment`), configured as:

| Config element | Value |

| Stimulus | one entry: population `sugar_grn_right` from the `id_sets_v1` artefacts (21 IDs), `rate_hz` = 200 (Amendment Pass 3; §3/A1) |
| Blocks | none |
| `duration_ms` | 1000 |
| `n_trials` | 30 |
| `seed` | 3000 → trial seeds 3000–3029 (the runner derives seed + trial index; the list is published here, in advance) |

**Why 30 trials.** The comparison is protocol-matched: the reference's means rest on 30 trials, and ours must carry the same sampling precision or the comparison confounds implementation differences with unequal noise. Thirty also exceeds Part 0's confirmatory floor (N = 20 seeds). The Part 0 N = 10 case does **not** apply here: that clause exists for deliberately mirroring the *old build's* canonical configuration, and the old build is not the reference for this rung — Shiu et al.'s released output is (plan §4.1's panel caveat: the old repo is a debugging aid, not a pass/fail target). The seed list is fixed by this document: disjoint from every Part 2 run (which used seed 0), published before any run, and **not** subject to re-rolling — a trial whose output looks odd stays in.

**Seed semantics.** Each seed initialises **all** stochastic components of its trial — in this model the only stochastic component is the Poisson drive — and the per-trial streams are independent across trials. A trial's output is reproducible from its own seed alone (seed 3000 + trial index, per the runner's derivation), without reliance on execution order or on any hidden global state: trial *k* run on its own produces the same spike table as trial *k* run inside the full sequence.

**Determinism (Reviewer 1, non-blocking).** Brian2 state is reset between trials: the runner builds a fresh seeded network per trial, so no state carries across trials; each trial's seed is independent; the CPU backend is deterministic. **Pre-declared engineering check (not a validation trial):** before the validation runs, run_id `part3-determinism-check` runs two 1-trial runs at seed 9999 under the frozen implementation; the two spike tables must be bit-identical (equal SHA-256). Same-seed reproducibility was already demonstrated in Part 2's tests; this check repeats it end-to-end through the frozen runner. If the tables differ, STOP and diagnose — a determinism failure voids the frozen implementation's reproducibility claim and blocks the validation runs.

**Seed-block allocation (fixed here, in advance).** The seed ranges are disjoint and published before any run: **3000–3029** the primary 200 Hz run (30 trials); **3030–3059** the 150 Hz sensitivity arm (§4.1); **3060–3089** the N = 60 extension (§4.2); **9999** the determinism engineering check above. No range is reused for any other purpose, no seed is used by more than one arm, and no seed is re-rolled. (Amendment Pass 3 swapped the rates attached to the first two blocks; the blocks themselves and their purposes are unchanged, and no run had used any of these seeds when the swap was made.)

**Projected wall-clock (measured, not estimated from the scaffold).** The Part 2 smoke run — same code path, same full network, one trial — took 103.2 s of simulation wall-clock, ~114 s whole-process including the per-trial network build from disk. Thirty trials run sequentially: **≈ 57 minutes projected, 2 hours budgeted** (the VM is shared; contention stretches wall-clock, not correctness). Analysis is minutes. The 150 Hz arm (§4.1) and the N = 60 extension (§4.2) each add ≈ 1 hour if they run. This is nowhere near the GPU trigger (14 days / 72 h per family, Part 0 §4) — the CPU reference platform stands, and K4 is not expected to be implicated.

**Run integrity.** The runner refuses a non-empty run directory, so a crashed or partial attempt voids the run: the attempt is logged, and the re-run takes a new `run_id`. No partial trial sets are ever analysed.

### 4.1 The 150 Hz sensitivity arm (pre-declared, non-confirmatory — Reviewer 1, R3; rate inverted by Amendment Pass 3)

The sensitivity arm exists because the 150 vs 200 Hz ambiguity is unresolved at the paper level (§3/A1) and important enough (K1 is on the line) not to be left to the last step of a diagnosis path. As originally pre-declared (Pass 2) the arm was 200 Hz against a 150 Hz primary; Amendment Pass 3 inverted the assignment on the reference-only discrimination evidence: the primary is now 200 Hz, and the arm is the other candidate rate, **150 Hz** — the code-default reconstruction, retained as an arm so the ambiguity is measured rather than assumed away. Configuration: identical to the primary run in every respect except `rate_hz` = 150 and the seed block **3030–3059**; run_id `part3-sugarR-150Hz-arm`; 30 trials × 1.0 s; same frozen implementation. It runs **only after the primary verdict is recorded**, takes ≈ 1 hour, and is labelled **non-confirmatory** throughout. Its result is evaluated under the same §8 rules applied to its own 30 trials, reported alongside the primary verdict, and governed by §8.2: it cannot change the primary verdict, and if it would have passed while the primary failed or was inconclusive, the verdict is annotated "protocol-ambiguous" and a corrected protocol needs its own new preregistration.

### 4.2 The N = 60 extension (precision-only, once — Reviewer 1, R5)

If — and only if — the primary result is inconclusive SOLELY because the MN9 95% CI half-widths exceed 15% of the reference means (the §8 precision gate), with no other criterion in an intermediate or fail band, ONE extension to N = 60 is allowed: 30 additional trials at the primary rate, 200 Hz, under the same frozen implementation and protocol, seeds **3060–3089**, run_id `part3-sugarR-200Hz-n60`, ≈ 1 hour. The comparison is then recomputed over all 60 trials against the reference's 30 (see §8.1 for the recomputation rules). The extension may be used once; if the result is still inconclusive afterwards, §8.1(b) applies.

## 5. Outputs compared

Both sides as spike tables in the shared schema. Reference: `sugarR.parquet` as verified at Part 1 (trials 0–29). Ours: the frozen run's `spikes.parquet` + `manifest.json` (the manifest must show the freeze commit and `dirty=False` for the run to count under this preregistration; a run under any other revision is a different revision's output and is reported as such, per the freeze rule).

## 6. Firing-rate computation (identical procedure on both sides)

- Per neuron, per trial: spike count with 0 ≤ t < 1.0 s, divided by 1.0 s → rate in Hz. (Every trial is exactly 1.0 s on both sides.)
- Per neuron: the **mean of the 30 per-trial rates**.
- **No burn-in, no transient trimming.** Upstream used none — its rates span the full window from a resting start (`v` initialised to `v_0` on both sides) — and trimming ours only would manufacture agreement. The onset transient is part of both outputs.
- **Inactive neurons are explicit zeros.** Rate tables are built over all 127,400 v630 IDs; a neuron absent from a spike table has rate 0 in every trial of that output. Which neurons then enter which statistic is defined by the comparison sets (§7), never by a table's accidental contents (ambiguity A3).

## 7. Comparison sets and statistics

**Active sets.** A neuron is *active* in an output if and only if it emits **at least one spike across the full 30-trial evaluation window** of that output — equivalently, its mean rate over the window is **> 0 Hz** (one spike in 30 s ≈ **0.033 Hz**, so the Hz form of the threshold is stated numerically, not left as prose). A_ref is the reference's active set — Part 1 counted **448**; the analysis first re-counts, and if the recount differs from 448 the analysis stops: the file being compared is not the file Part 1 verified. A_ours is ours, defined identically.

**Primary comparison set: the union U = A_ref ∪ A_ours.** A neuron active on only one side enters with rate 0 on the other — asymmetric activity is disagreement and must be priced into the correlation, not excluded from it. Neurons silent on both sides carry no information about agreement and are excluded from the correlations (they are counted and reported). The reference-only set A_ref is the secondary set, reported for continuity with the old build's framing. The **same** union set U is used identically for the Spearman correlation, the Pearson correlation and the (unthresholded) Jaccard, precision and recall — the comparison set is never varied per metric. (The 0.1 Hz and 1 Hz columns of the sensitivity table in §7 item 3 are pre-declared variants; they do not redefine the comparison set for any other metric.)

**Statistics** (all computed by an analysis script written for this rung, itself tested on synthetic spike tables with known agreement before it touches the real outputs — §9, step 1):

1. **Primary metric: Spearman rank correlation** between the two mean-rate vectors over U (Part 0 §2.1: Spearman on the active subset is the benchmark's primary metric).
2. **Secondary:** Pearson correlation over U; Spearman and Pearson over A_ref.
3. **Set overlap and sensitivity table.** Jaccard(A_ref, A_ours); precision = |A_ref ∩ A_ours| / |A_ours|; recall = |A_ref ∩ A_ours| / |A_ref| — computed at the primary active definition (≥ 1 spike in 30 trials) **and** at two further thresholds, **0.1 Hz** and **1 Hz** mean rate, as a pre-declared sensitivity table (Reviewer 1, R4): all three thresholds are reported for all three metrics. The PASS/FAIL floors in §8 apply at the primary threshold; the other two columns are reported alongside so a threshold-sensitive result cannot hide. The ≥ 1 Hz column is the "reliably active" variant (not one-spike noise).
4. **Cross-replicate noise ceiling (estimated for BOTH datasets).** Split-half reliability is estimated separately for the reference and for our output, and separately for each correlation type (Spearman and Pearson, each computed with its own correlation type). Method, fixed here: **200 balanced splits**; for each split, the 30 trial indices are partitioned at random into two halves of 15 (without replacement), the partitions generated under a **fixed split seed, 20261123**, published here in advance; each half's mean-rate vector over U is computed; the correlation between the halves (Spearman, resp. Pearson) is corrected to full 30-trial reliability with the Spearman–Brown formula, R = 2ρ_half / (1 + ρ_half); the corrected values are averaged over the 200 splits. This gives **R_ref,30** (reference) and **R_new,30** (ours), per correlation type. The **cross-replicate ceiling** is **C_cross = √(R_ref,30 × R_new,30)**, again per correlation type (C_cross,Spearman for the primary metric; C_cross,Pearson for the secondary). R_ref,30, R_new,30 and C_cross are **reported alongside the observed correlations** in every report of this rung. The ceiling estimates the agreement **two independent 30-trial runs of the same model** would show — it is the honest bound for a seeded-vs-unseeded comparison (§8 rationale) — and it is an *estimate*, not a constant (§7 item 7). This replaces the draft's reference-only, single odd/even split ceiling (Amendment Pass 1, Reviewer 3).

**Identical pipeline (Reviewer 1, R2).** The ceiling is computed through the identical `compare_outputs` code as the main comparison (`repo/fresh/part3/compare.py`): the same union-active-set construction, the same mean-rate vectors, the same Spearman and Pearson computations. **Tie handling, written down:** Spearman ranks use average ranks for tied values (scipy.stats.spearmanr default); many ties at 0 are expected, because most neurons in the union set are silent on at least one side and the union set is dominated by low-rate neurons. The halves' union set is built from the halves themselves by the same code — a neuron active in a half is necessarily active in the full 30-trial window, so the halves' support is a subset of the full support, never an ad-hoc redefinition. **Our own split-half is reported too:** after the runs, R_new,30 is computed by the same 200-split machinery (seed 20261123), and the odd/even split-half (odd trials vs even trials, same Spearman–Brown correction) is reported as an additional quantity — the odd/even split can only be computed after the runs, so it is recorded here as a to-be-reported quantity, while the reference's component is pre-recorded now (§2.1). **Pre-recorded:** R_ref,30 is Spearman 0.9995 and Pearson 0.9998 (§2.1) — the "ceiling below 0.90 → INCONCLUSIVE" branch would require R_new,30 < 0.81, so it is retained as a guard but is not expected to fire.
5. **MN9 endpoints.** MN9 left (720575940660219265) and right (720575940645521262), reported separately, always: per-trial rates on both sides; mean and **95% CI by percentile bootstrap over trials, 10,000 resamples** (Part 0 §2.3 method; fixed bootstrap seed **20261124**, declared in advance in §2.1), computed identically for the reference (expected means from Part 1: L 93.3 Hz, R 61.8 Hz; pre-recorded with CIs in §2.1) and for ours. The agreement *decision* on these endpoints is the difference/equivalence test of §8 (PASS clause 4), which uses Δ between the two means with its own bootstrap CI; the CIs here are reported alongside it.
6. **Distribution-level diagnostic (reported, not a criterion):** over U, the per-neuron differences (ours − reference): median and IQR; and the fraction of U whose rates agree within the Part 0 band (±25% of the reference rate, or ±5 Hz, whichever is wider). This is pre-declared a *diagnostic*: it may inform a diagnosis, but it cannot be promoted into a pass/fail criterion after the fact.
7. **Uncertainty on the correlations and the ceiling.** Trial-resampling uncertainty (percentile bootstrap over trials, 10,000 resamples — the Part 0 §2.3 resampling method applied over trials) is reported for **both** the observed correlations (Spearman and Pearson over U) **and** the ceiling estimate C_cross (per correlation type). The ceiling enters the §8 bands as a point estimate, but it is reported and discussed as an estimate with its interval — never as a fixed constant.

**Gap bootstrap (Reviewer 1, R1; feeds the §8 PASS rule).** In addition, the gap to the ceiling is bootstrapped: B = **2,000 nested replicates**; in each replicate, 30 trials are resampled with replacement from our trials AND 30 from the reference's trials, the mean-rate vectors and the union set U are recomputed by the same code, the observed correlations are recomputed, and C_cross is recomputed within the replicate from **50 balanced splits** (the first 50 of the split sequence under seed 20261123). The gap is **signed**, by explicit definition (Reviewer 3, Amendment Pass 3): **G = C_cross − ρ_observed** for Spearman, and **G_Pearson = C_cross,Pearson − r_observed** for Pearson. In each replicate, gap_b = C_cross,b − ρ_b (Spearman) and the Pearson analogue, computed with the same signed definition. A negative gap means the observed correlation **exceeds** the ceiling; that is never penalised — every gap condition in §8 is applied to the signed gap, never to an absolute difference. The computations operate on the union-set rows only: a neuron active in any resampled or split window is necessarily active in the full window, so the restriction is exact, not an approximation. The 95th percentile of each gap distribution is reported and used in §8.

No multiple-comparison correction applies: the verdict is a fixed conjunction over the small named metric set above, not a search over hypotheses. (Holm, per Part 0 §2.3, governs the intervention experiments' metric families.)

## 8. Tolerances — PASS / INCONCLUSIVE / FAIL

**Why the tolerances are anchored to the noise ceiling, not to 1.0.** Upstream's code is unseeded: two runs of *upstream itself* would not produce identical outputs, only statistically similar ones. Demanding correlation 1.0 (or any fixed near-1.0 value) from our seeded implementation would demand something the reference cannot do against itself — a bitwise standard dressed as a scientific one. The cross-replicate ceiling (§7 item 4) measures what "the same model, run again" actually achieves — on both sides of the comparison, since our output's own trial-to-trial variability bounds the observable correlation just as the reference's does. The tolerances below require us to be within Part 0's benchmark agreement tolerance (±0.02, §2.3 — fixed at Part 0 for the named primary metric) of that ceiling, with absolute floors so a degenerate ceiling cannot make the test meaningless in either direction. **Shortfall, defined once:** "within 0.02 of the ceiling" means **observed ≥ C_cross − 0.02** — 0.02 is a *maximum permitted shortfall*, not a target. An observed correlation may exceed the ceiling; exceeding it carries no penalty and needs no explanation beyond noting it. The ceiling is an estimate with bootstrap uncertainty (§7 item 7), not a constant. The old build's numbers against this same reference (Pearson 0.9936, Jaccard 0.9113, precision 0.9928, recall 0.9174 — Part 0 §2.1) are disclosed alongside the floors; the floors' justification rests on the reference-only split-half analogue, not on the old build (see PASS clause 3).

**Overall rule (Reviewer 1, R1 — stated explicitly).** PASS only if ALL criteria in the PASS list are met, including the gap upper bounds. FAIL if ANY FAIL trigger fires. Anything else is INCONCLUSIVE. The FAIL triggers are point-based; the gap bootstrap interval gates PASS only — a straddling interval can demote a PASS to INCONCLUSIVE, but never converts a FAIL into an INCONCLUSIVE. Each named metric falls into a PASS, FAIL or intermediate band under the rules below, and the rung's verdict is the **worst applicable band across metrics**: PASS requires every metric in its PASS band; any metric in its FAIL band makes the verdict FAIL; anything else is INCONCLUSIVE. This governs mixed cases explicitly — e.g. Spearman in its PASS band while Pearson sits in its intermediate band is INCONCLUSIVE, not PASS.

**PASS — all of:**
1. Spearman ρ over U ≥ C_cross,Spearman − 0.02 **and** ρ ≥ 0.90 **and** the 95th percentile of the gap bootstrap distribution for the **signed** Spearman gap **G = C_cross,Spearman − ρ_observed** ≤ 0.02 (§7 item 7). The condition applies to the signed gap, not an absolute difference: an observed correlation above the ceiling gives a negative G and passes this clause by construction.
2. Pearson r over U ≥ C_cross,Pearson − 0.02 **and** the 95th percentile of the gap bootstrap distribution for the **signed** Pearson gap **G_Pearson = C_cross,Pearson − r_observed** ≤ 0.02 (§7 item 7), with the same signed-gap rule.
3. Jaccard(A_ref, A_ours) ≥ 0.85, precision ≥ 0.90, recall ≥ 0.85 — at the primary active definition (§7 item 3). **Justification, re-stated (Reviewer 1, R4):** the floors sit below the reference-only split-half analogue — the same model scored against itself over 200 balanced 15/15 splits gives Jaccard 0.974, precision 0.987, recall 0.987 at the primary threshold (0.975 / 0.988 / 0.987 at 0.1 Hz; 0.978 / 0.989 / 0.989 at 1 Hz; §2.1) — with room left for seeded-vs-unseeded variation, and the 15-trial halves are a conservative analogue (smaller active sets than a 30-trial comparison). The floors also sit below the old build's achieved values (Jaccard 0.9113, precision 0.9928, recall 0.9174). **Stated openly: those old-build values were seen when the floors were chosen** — the split-half analogue is the justification; the old values are disclosed, not hidden.
4. **MN9 agreement — the difference/equivalence test** (Amendment Pass 1, Reviewer 3; this replaces CI-overlap as the decision): for each of L and R, let Δ = (our mean rate) − (reference mean rate), with a **95% CI for Δ** by percentile bootstrap over trials on both sides (10,000 resamples, the §7 item 5 method). Agreement requires the CI for Δ to lie **entirely within the equivalence margin of ±25% of the reference mean rate** — Part 0 §2.4's rule (±25%, or ±5 Hz, whichever is wider), stated numerically: **±23.3 Hz for L** (25% of 93.3 Hz) and **±15.5 Hz for R** (25% of 61.8 Hz); the ±5 Hz floor is not binding for either neuron. The Part 0 §2.3 CI-overlap rule (the reference mean inside our 95% CI, or ours inside the reference's) is still computed and **reported, but it is reporting only — it no longer decides agreement**. **And** the L > R ordering of the point estimates is preserved (on the ordering's source, see §10).

**FAIL — any of:**
1. Spearman ρ more than 0.05 below C_cross,Spearman (ρ < C_cross,Spearman − 0.05), or ρ < 0.80 regardless of the ceiling.
2. Pearson r more than 0.05 below C_cross,Pearson (r < C_cross,Pearson − 0.05), or r < 0.80 regardless of the ceiling.
3. Jaccard < 0.75.
4. MN9 ordering reversed (our R ≥ our L) with non-overlapping 95% CIs.
5. **MN9 deviation beyond the FAIL band under the difference/equivalence test:** for either neuron, |Δ| exceeds **50% of the reference mean rate** (numerically: L 46.6 Hz; R 30.9 Hz) **and** the 95% CI for Δ lies entirely outside the equivalence margin (it does not intersect [−margin, +margin]).

**INCONCLUSIVE — anything between the bands, and specifically:**
- any metric lands between its PASS and FAIL lines — including the Pearson intermediate band (C_cross,Pearson − 0.05 ≤ r < C_cross,Pearson − 0.02, with r ≥ 0.80) while Spearman passes, per the worst-band rule above; or
- the gap bootstrap straddles the tolerance for either correlation — the signed point gap (G, §7 item 7) is ≤ 0.02 but its 95th percentile exceeds 0.02 (the result is consistent with the tolerance and consistent with exceeding it; the same equivalence logic as TOST in FINAL-PLAN §5.6); or
- an MN9 CI for Δ neither lies entirely within the equivalence margin (PASS clause 4) nor meets FAIL clause 5; or
- C_cross,Spearman < 0.90 — the two outputs' combined trial noise is too large for this comparison to discriminate, so the rung can neither convict nor acquit; or
- our MN9 95% CI half-widths exceed 15% of the reference means (Part 0 §2.2's precision target missed — the comparison is under-powered, which is a statement about precision, not about the model). This 15% rule is a **precision gate**: it stays in force alongside the equivalence test, and exceeding it makes the rung INCONCLUSIVE, never FAIL.

An inconclusive verdict is a reported result of this rung, not a failed run and not a quiet pass. Its paths are pre-registered in §8.1 — it goes to the gate with its diagnosis and options for Angelic's decision. Seeds are never re-rolled to convert an inconclusive or a fail into a pass.

### 8.1 Paths out of INCONCLUSIVE (Reviewer 1, R5)

An inconclusive verdict is a reported result, and its path is fixed here, not improvised at the gate:

(a) **Precision-only extension, once.** If the result is inconclusive ONLY because the MN9 95% CI half-widths exceed 15% of the reference means (the §8 precision gate) — and no other criterion is in an intermediate or fail band — ONE extension to N = 60 is allowed: 30 additional trials at the primary rate, 200 Hz, under the same frozen implementation and protocol, seeds **3060–3089** (seed-block allocation, §4), run_id `part3-sugarR-200Hz-n60`. The comparison is then recomputed over all 60 trials against the reference's 30: the active set is redefined over the 60-trial window; the ceiling becomes C_cross,60 = √(R_ours,60 × R_ref,30), with R_ours,60 from 200 balanced 30/30 splits of our 60 trials corrected to 60 trials; the MN9 CIs are recomputed from 60 trials and the gap bootstrap resamples 60 trials from ours and 30 from the reference's; the PASS/FAIL bands of §8 apply unchanged with C_cross,60 in place of C_cross. The original 30 trials are retained, never replaced. If the result is still inconclusive after the extension, path (b) applies.

(b) **Any other inconclusive outcome** — including a gap-bootstrap straddle, an intermediate Pearson/Spearman band, or a still-inconclusive result after the N = 60 extension — goes to the gate for a panel decision, or a logged waiver signed by Angelic following the §0.2(c) pattern (a signed, dated record that the decision path was followed — the same discipline as the expert-check waiver in PART0-PACKAGE §6.3: the mitigation may fail, it may never *silently* not happen).

### 8.2 The 150 Hz arm and protocol-ambiguity (Reviewer 1, R3; inverted by Amendment Pass 3)

The 150 Hz sensitivity arm (§4.1) runs only after the primary verdict is recorded, under the same §8 rules applied to its own 30 trials. Its result is reported alongside the primary verdict, labelled non-confirmatory, and it **cannot change the primary verdict**: if the primary (200 Hz) is FAIL or INCONCLUSIVE and the 150 Hz arm would have passed, the verdict stays FAIL or INCONCLUSIVE, annotated **"protocol-ambiguous"**. A corrected (150 Hz) protocol then needs its own new preregistration — the pass bar cannot be moved after the fact by pointing at the arm. ## 9. On FAIL — the diagnosis path, and the kill criterion

Per the plan's discrepancy rule (§4): STOP, log, diagnose — in this pre-set order, each step's outcome recorded before the next begins:

1. **The analysis code first.** The comparison script is re-verified on synthetic spike tables with known agreement (identical tables, shifted tables, disjoint tables) — a bug in the measuring instrument is the cheapest explanation and is excluded first.
2. **Run provenance.** The run manifest: freeze commit, dirty flag, data hashes, environment — any deviation voids the run, not the model.
3. **The driven set.** The 21 driven IDs and their Brian indices re-checked against `id_sets_v1` and the index↔ID verification.
4. **The drive.** Rate, kick size (68.75 mV into `v`), and refractory handling re-read against the reading log and the frozen code.
5. **The weights.** The sampled sign audit (count × sign vs the file's own product column) re-run; loader counts re-verified.
6. **The numerics.** dt, integration method, reset string — including the `w` position (ambiguity A4) — re-checked against the spec.
7. **Only then**, model-level divergence as an explanation (e.g. Brian2 version differences between our pinned 2.9.0 and upstream's environment), and only with evidence, not as a resting place. Ambiguity A2 (the protocol is a reconstruction) is interrogated here, last, deliberately.

**No parameter is re-fit during diagnosis.** `w_syn` stays at the paper's 0.275 mV, and every other parameter stays at its reading-log value. Tuning toward the reference would convert validation into fitting; any proposal to change a parameter is a formal amendment that voids this rung's confirmatory status and must say so.

**Kill criterion implicated: K1.** If, after these logged diagnosis steps, the standard still is not met, Part 3 has failed to reproduce the paper's feeding pattern: the project pivots to the **reproduction-failure report** (itself a publishable output, plan §9.1/§10) and does **not** proceed to embodiment on an untrusted brain. K4 would be implicated only if compute — not correctness — blocked the pre-registered design; at ≈1 hour projected, it is not expected. K2, K3, K5, K6 are not implicated by this rung.

**The 150 Hz arm is not a diagnosis step.** It runs after the verdict is recorded (§8.2), under its own rules. If the primary FAILs, the diagnosis path above runs first; ambiguity A2 (the protocol is a reconstruction) is interrogated at step 7, last — and it has a known candidate, the drive rate (§3/A1): the reference-only evidence favours 200 Hz, but if the 200 Hz primary fails, the possibility that the code-default 150 Hz was the generating rate after all is exactly what step 7 must weigh with evidence, not assume away in either direction. A failed primary does not become a passed 150 Hz primary by re-labelling; a corrected protocol needs its own new preregistration.

## 10. RQ-C5 handling (the MN9 asymmetry)

The reference shows a strong asymmetry under right-only sugar drive (L 93.3 Hz vs R 61.8 Hz), and the old build reported a similar one (83.5 vs 58.7 Hz). Whether that asymmetry is a real circuit property, an artefact of the unequal GRN set sizes (21 right vs 10 left), or a bug is **RQ-C5 — an open hypothesis, and it stays open through this rung** (Reviewer 2's Part 2 gate condition; register A14/G1 cross-reference).

**Source of the L > R ordering requirement (§8, PASS clause 4).** The ordering is a property of the **`sugarR` reference output itself** — in the reference data, MN9 left fires at 93.3 Hz and MN9 right at 61.8 Hz (§2). Requiring our reproduction to preserve it is a model-vs-model benchmark check against that output. It is **not** a biological assumption about living flies, and it is **not** inherited from the old build's ordering (the old build's similar numbers are a Part 6 comparison target, §11, nothing more). RQ-C5's question is *whether* the asymmetry is real, an artefact, or a bug — never, on this rung's evidence, *why* — and using the reference's own ordering as a reproduction criterion leaves that question exactly as open as it was.

What this rung's numbers are: the first multi-trial, seeded, fully manifested MN9 L/R measurements of the fresh build — RQ-C5's first real evidence, reported with CIs, L and R always separate, never pooled. What they may support saying: whether the asymmetry *appears* in our reproduction, and how large it is. What they may not support: any claim about *why*. The resolution belongs to Part 3's dedicated RQ-C5 runs (bilateral and unilateral stimulation at matched GRN counts, plan §8.1), pre-registered separately. One boundary, stated in advance so it cannot blur later: an MN9 ordering reversal here is a **benchmark FAIL trigger** (§8) because it contradicts the reference output — a statement about reproduction. It is not, by itself, a finding about the asymmetry's cause, and no write-up may present it as one.
